# Design: Issue #443 performance batch

**Issue:** [#443](https://github.com/accelas/mango-option/issues/443) — Build/query-time performance: move-from-const copies coefficient tensor, Greeks evaluate interpolant twice, misc

**Branch:** `fix/443-perf-batch`

## Scope

Issue #443 lists six minor performance findings. This change fixes items 1, 2, 4
(first half), 5, and 6. All were re-verified as still present at HEAD
(`e2fd4bf3`) except where noted.

Out of scope:

- **Item 3** (`AmericanOptionResult::gamma()` allocations) — the same lines are
  being changed by the in-flight #438 correctness fix (PR #467). Deferred so the
  two don't conflict; noted on #438.
- **Item 4, second half** (`.value()` on `from_bytes` inside an OpenMP region) —
  already fixed: the #457 parallel-safety refactor replaced the workspace path
  with `factorize()`/`solve_factored()` and plain per-thread vectors. No
  `from_bytes` callers remain in the fitting path.
- The per-slice LU refactorization mentioned at the bottom of the issue —
  already landed with #435/#457 (`factorize()` once per axis).

## Decisions

Captured from triage (no brainstorm needed — fixes are prescribed by the issue;
one scoping question was put to the user):

- **D1 (user decision): skip item 3 here.** The perf half of gamma() rides with
  or follows PR #467 (issue #438), which already touches those exact lines.
- **D2: fix item 2 by deleting the redundant guard, not by threading values.**
  `TransformLeaf::greek()`/`gamma()` already return `0.0` when the raw
  interpolant value is `<= 0`, which makes `EEPLayer`'s `raw_value()` pre-check
  semantically a no-op: `0.0 + european == european`. Removing the pre-check
  eliminates one redundant raw-value evaluation per Greek/gamma query with no
  API change. `raw_value()` itself is retained (public, tested).
  *Design-review round 1 disagreed*, proposing to keep the guard and add a
  `greek_from_raw()` optimized path with the old flow as fallback for custom
  leaves. Disagreement recorded and overridden: `EEPLayer` has exactly four
  instantiations in this codebase, all `TransformLeaf`; there is no
  third-party-leaf compatibility requirement, and a second conditional code
  path is worse than one path plus an explicit, *tested* leaf contract
  (see Design §2 and Testing).
- **D3: fix item 6 with immediate stall detection, replacing the `iter > 10`
  overshoot check.** After clamping, `x_clamped == x` means the next iteration
  would re-evaluate `f`/`df` at the identical point — return `NoProgress`
  right away.
- **D4 (amended in design review): fix item 4 by constructing the 1D solvers
  once in `create()`** and passing them into the private constructor, instead
  of validate-and-discard followed by reconstruction. The `grids_` member is
  removed: grids are only used to derive `dims_` and the expected tensor size,
  so `create()` captures `dims[i] = grids[i].size()` and then *moves* each
  grid into `BSplineCollocation1D::create()` — zero grid copies, no duplicate
  grid storage.
- **D5: item 5 is a documentation fix only**, per the issue text ("fine as a
  convenience API; should be documented").

## Design

### 1. Move-from-const copies the coefficient tensor

`src/option/table/bspline/bspline_builder.cpp:521-528`

```cpp
const auto& result = fit_result.value();      // const lvalue ref
...
.coefficients = std::move(result.coefficients)  // selects the COPY ctor
```

**Fix:** drop the `const` (`auto& result = fit_result.value();`). The
`std::move` then genuinely moves the (Nm·Nτ·Nσ·Nr) coefficient vector.
This matches the correct pattern already used at line 180 of the same file.

No behavior change; `fit_result` is a local consumed here.

### 2. EEP Greek path evaluates the interpolant twice

`src/option/table/eep/eep_layer.hpp:42,67` + `src/option/table/transform_leaf.hpp:56-57,76-77`

Current flow for `EEPLayer::greek()`: call `leaf_.raw_value()` (one
`to_coords` + `interp_.eval`), branch on `raw <= 0.0`, then call
`leaf_.greek()`, which redoes `to_coords` + `interp_.eval` before its own
identical `raw <= 0.0` branch. Same duplication in `gamma()`.

**Fix (per D2):** in `EEPLayer::greek()` and `EEPLayer::gamma()`, remove the
`raw_value()` call and the early return. Unconditionally:

```cpp
auto leaf_greek = leaf_.greek(g, params);
if (!leaf_greek.has_value()) return std::unexpected(leaf_greek.error());
return *leaf_greek + european;
```

Equivalence argument: every `Leaf` used with `EEPLayer` is a `TransformLeaf`
instantiation (`BSplineLeaf`, `ChebyshevLeaf`, 3D variants — the serialization
`reconstruct.hpp` path produces the same four specializations), and
`TransformLeaf::greek`/`gamma` return `0.0` (not an error) when the raw
interpolant value is `<= 0`. So the deep-OTM result is unchanged:
`0.0 + european == european`. The docstring "When leaf EEP is zero (deep OTM),
returns European Greek only" stays true and stays on `EEPLayer::greek`.
Segmented (MultiKRef) leaves are not wrapped in `EEPLayer` — unaffected.

Known, accepted behavioral deltas (production-invisible today):

- If a future leaf's `greek()`/`gamma()` returned an *error* deep OTM, it now
  propagates instead of being suppressed. `TransformLeaf` has no error paths,
  so no current caller can observe this; propagating is the intended contract.
- Signed zero: deep OTM, `0.0 + european` can turn a `-0.0` European Greek
  into `+0.0`. Numerically indistinguishable (`==` holds).

The leaf concept does not formally require the raw-`<= 0` ⇒ `greek() == 0.0`
contract; this change makes `EEPLayer` rely on it. Two mitigations:
document the requirement in the `EEPLayer` class comment, and pin it with a
deterministic `TransformLeaf` contract test (see Testing) so the reliance is
tested, not silent.

This eliminates the one redundant raw-value evaluation (`to_coords` +
`interp_.eval`) per Greek/gamma query. (The derivative evaluations inside
`greek()` itself — partials, and gamma's FD fallback — are unchanged and
were never duplicated.)

`raw_value()` keeps its public definition and tests; its doc comment ("for
EEP layer guard") is updated since `EEPLayer` no longer calls it.

The mock leaf in `tests/eep_greeks_test.cc` implements `raw_value()`; it must
be updated so its `greek()`/`gamma()` honor the same zero-contract (return 0
when its raw value is `<= 0`), keeping the deep-OTM tests meaningful.

### 4. `BSplineNDSeparable::create` constructs every 1D solver twice

`src/math/bspline/bspline_nd_separable.hpp:125-141,244-267`

`create()` builds a `BSplineCollocation1D` per axis purely to validate, and
discards it (each construction copies the grid vector into
`BSplineCollocation1D::create(std::vector<T> grid)` by value). The private
constructor then builds all N solvers again, with an `assert` standing in for
the already-discarded validation.

**Fix (per amended D4):**

```cpp
static std::expected<BSplineNDSeparable, InterpolationError> create(
    std::array<std::vector<T>, N> grids)
{
    std::array<size_t, N> dims;
    std::array<std::unique_ptr<BSplineCollocation1D<T>>, N> solvers;
    for (size_t i = 0; i < N; ++i) {
        dims[i] = grids[i].size();
        auto solver_result = BSplineCollocation1D<T>::create(std::move(grids[i]));
        if (!solver_result.has_value()) {
            auto err = solver_result.error();
            err.index = i;
            return std::unexpected(err);
        }
        solvers[i] = std::make_unique<BSplineCollocation1D<T>>(
            std::move(*solver_result));
    }
    return BSplineNDSeparable(dims, std::move(solvers));
}
```

The private constructor takes `(dims, solvers)` and keeps only the strides
computation; the second construction loop and its `assert` disappear. The
`grids_` member is removed entirely — inside the class, grids were only used
to derive `dims_` and the expected tensor size, and `fit()`'s size check
switches to `dims_`. (No public grid accessor exists; nothing else reads
`grids_`.)

Per axis this is 0 grid copies + 1 solver construction instead of
2 copies + 2 constructions, and duplicate grid storage for the fitter's
lifetime goes away. Error semantics (`err.index = i`) are preserved.

### 5. `AnyPriceTable::solve_iv` builds a solver per query

`src/option/price_table_factory.cpp:880-888`, declaration at
`src/option/price_table_factory.hpp:59-61`

Behavior is intentional (convenience API). **Fix (per D5):** add a doc comment
on the declaration:

```cpp
/// Convenience one-shot IV solve. Constructs a fresh solver (bounds
/// extraction + variant dispatch) on every call — not intended for
/// repeated or hot-path queries. For those, create the solver once via
/// make_iv_solver() and reuse it.
```

No code change.

### 6. Newton wastes ~11 evaluations stalled at a clamped bound

`src/math/root_finding.hpp:420-438`

When the Newton step leaves `[x_min, x_max]`, `x` is clamped to the bound. If
the root lies outside the bounds, every subsequent iteration recomputes the
same step from the same point — `f`/`df` are re-evaluated at an identical `x`
for iterations 0..10 before the `iter > 10` overshoot check finally errors.

**Motivation (corrected in design review round 1):** at current HEAD,
`newton_find_root` has *no production callers* — both the FDM IV solver
(`iv_solver.cpp`) and the interpolated IV solver
(`interpolated_iv_solver.hpp`) use Brent; only the root-finding tests
exercise Newton. The issue's "wasted PDE solves" framing is therefore stale.
The fix stays in this batch as generic library-routine cleanup (it is
explicitly item 6 of issue #443), benefiting any future Newton adoption.
The stale doc claims that `InterpolatedIVSolver::solve` uses Newton-Raphson
are part of issue #442 (doc/code mismatches) and remain out of scope here.

**Fix (per D3):** replace the `iter > 10` overshoot check with stall
detection:

```cpp
const double x_clamped = std::clamp(x_new, x_min, x_max);

// No movement (clamped onto the bound we're already at, or zero-size
// step): the next iteration would re-evaluate the same point.
if (x_clamped == x) {
    return std::unexpected(RootFindingError{
        .code = RootFindingErrorCode::NoProgress,
        .iterations = iter + 1,
        .final_error = error_abs,
        .last_value = x_clamped});
}

x = x_clamped;
```

Properties:

- Root outside bounds: iteration 0 moves `x` to the bound (or the clamped
  initial guess is already there), iteration 1 detects the stall — ≤ 2
  evaluations of `f`/`df` instead of ~11.
- A step that overshoots a bound but later re-enters the interior keeps
  iterating (`x_clamped != x` whenever `x` actually moves) — this *removes*
  the old behavior where any overshoot after iteration 10 aborted even though
  the iterate was still moving.
- `x_clamped == x` with no bound involved means the Newton increment
  underflowed to zero while `|f(x)| >= tolerance`; `NoProgress` is the correct
  verdict there too (nothing can change on later iterations).
- Exact `==` comparison is intentional: it is true precisely when the next
  `f(x)`/`df(x)` calls would receive bit-identical input.
- Error code and fields are unchanged, as is the earlier flat-derivative check
  (`|df| < 1e-10` → `NoProgress`); only *when* the clamped-bound `NoProgress`
  fires changes.

Callers: none in production (see motivation above); the root-finding tests
that assert `NoProgress` semantics are updated alongside.

## Testing

- **Item 2 leaf-contract tests** (`tests/transform_leaf_greeks_test.cc`):
  deterministic — a `TransformLeaf` built over a fake interpolant that returns
  exactly `0.0` (and one returning a negative value); assert `greek()` and
  `gamma()` return exactly `0.0` (not merely finite) and that no derivative
  (`partial`) evaluation occurs. This pins the raw-`<= 0` ⇒ `0.0` contract
  `EEPLayer` now relies on. (The existing `ReturnsZeroWhenRawNonPositive`
  cases only assert finiteness — tighten or supplement them.)
- **Item 2 single-evaluation regression test** (`tests/eep_greeks_test.cc`):
  counting mock leaf — assert one `EEPLayer::greek()` call makes exactly one
  leaf `greek()` call and zero `raw_value()` calls (same for `gamma()`).
  Existing deep-OTM tests verify the European-only result is preserved (mock
  updated per D2 to honor the zero-contract).
- **Item 6 regression tests** (root-finding test file), counting `f` and `df`
  calls separately and asserting exact error fields (`NoProgress` code,
  `iterations`, `last_value` at the bound):
  - Initial guess clamped onto the stalled bound (root outside bounds):
    exactly 1 `f` + 1 `df` call.
  - Interior start whose first step clamps to the bound, then stalls:
    exactly 2 `f` + 2 `df` calls.
  - Overshoot-then-reenter-then-converge, e.g. `f(x) = (x-1)(x+0.2)` with
    `x0 = 0.5`, bounds `[0, 2]`: first step overshoots to the upper bound,
    later steps re-enter and converge to the interior root — expect success
    (guards against over-eager stall detection).
- **Item 4 regression test** (`bspline_nd_separable` tests): invalid grid on a
  *later* axis with earlier axes valid — assert `error().index` equals that
  axis (existing factory-failure tests only assert the error code). Everything
  else is behavior-preserving and covered by the existing fitter/builder
  suites (140 tests green pre-change must stay green).
- **Item 1**: behavior-preserving; covered by existing builder tests.
- **Item 5**: doc only, no test.
